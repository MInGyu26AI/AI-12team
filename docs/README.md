# SyncUp — 서버 구현 안내

팀원들이 각자 AI와 나눈 대화에는 결정, 할 일, 조사 결과가 흩어져 있습니다. SyncUp은 이 내용을 공유 후보로 정리하고, 사용자가 확인해 승인한 항목을 팀 보드에 모읍니다. 이미 공유된 결정과 다른 내용이 들어오면 비교 결과를 보여줍니다.

이 문서는 `server` 브랜치의 구현과 검증 범위를 설명합니다.

## 사용 흐름

1. 사용자가 수집할 프로젝트와 팀을 선택합니다. Codex·Claude Code의 새 대화와 Chrome 확장·내보내기·붙여넣기 입력을 처리합니다.
2. 로컬에서 비밀정보를 가리고 개인 내용을 검사합니다. 통과한 문구만 외부 AI에 보내 결정·할 일·조사 후보로 정리합니다.
3. 사용자가 후보와 근거를 확인하고 공유할 항목을 승인합니다. 팀 공유 승인과 외부 AI 분석 동의는 별개입니다.
4. 승인한 항목은 선택한 팀 보드에 저장됩니다. 새 결정은 기존 결정과 비교하고, 확인이 필요한 결과를 표시합니다.

## 핵심 설계

| 해결할 문제 | 구현한 방식 |
|---|---|
| 개인 사정이나 비밀키가 대화에 섞임 | 외부 AI 요청 전 규칙 마스킹과 로컬 모델 검사. 오류·애매한 응답은 보류 |
| 개인 초안이 팀에 바로 공유됨 | 개인 검토와 팀 저장소 분리. 승인한 문구·근거만 전송 |
| 여러 팀의 자료가 섞임 | 승인 목적지 고정과 서버의 팀 소속 검증, DB 행 수준 접근 제어 |
| AI가 불확실한 비교를 완료로 처리함 | 확신도 0.6 기준 유지. 낮은 확신도는 독립 검토와 재확인 결과가 일치해야 수용 |
| 비교 도중 끊겨 처음부터 반복함 | 완료한 비교와 진행 상태를 함께 저장하고 남은 쌍부터 재개 |

[데이터 흐름과 처리 경계](design.md) · [분류 기준과 예시](classification.md)

## 검증 요약

| 확인한 내용 | 결과와 범위 |
|---|---|
| 현재 개인정보 필터 | 공유본 32개·원본 29개 회귀 검사 통과. 양쪽에서 실제 QAT 모델과 임시 DB로 개인·혼합·키 포함 입력 확인 |
| 결정 비교 개선 | 기존 96회 평가의 완료 73→78회, 기존 성공 사례의 퇴행과 완료된 판정의 오답 0. 나머지 18회는 보류 |
| 중단 복구 | 임시 PostgreSQL에서 65개 비교 완료 및 프로세스 재시작 복구. 브라우저에서 7/40 중단 후 40/40 완료 |
| 팀 격리·승인 | 임시 DB와 실제 HTTP에서 타 팀 접근 차단, 동일 승인 재전송, 변경된 중복 요청 거절 검증 |

합성 사례와 통제된 환경의 결과입니다. 실제 사용자 대화 전반의 정확도나 개인정보 유출률 0을 보장하지 않습니다. [검증 방법·근거·남은 한계](verification.md)에서 실제 모델 검사와 모의 응답 검사를 구분했습니다.
