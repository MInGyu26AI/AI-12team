# 로컬 개인정보 필터: QAT와 정책 v3

2026-11-09. 현재 기본 모델은 `gemma4:e4b-it-qat`, 정책은 `syncup-local-privacy/3`이다. 문맥 8192, 유휴 유지 60초, temperature 0, seed 7, think=false를 사용한다. `SYNCUP_LOCAL_PRIVACY_MODEL`의 명시적 설정은 기본값보다 우선하며 빈 값이나 미설치 모델은 보류한다. 검증 환경은 Ollama 0.40.15, 모델 digest `ee665637121887cf3befff38abbb1be4ee117c7db867d97a67e29049ecd7e15f`다.

## 범위와 안전 경계

- 구조화 응답을 지원하지 않는 HTTP 501에서만 형식 제약을 제거해 한 번 대체 요청한다. 다른 통신 오류를 이 경로로 무시하지 않는다.
- 완전한 JSON 객체 하나 또는 그 객체만 감싼 코드 블록을 허용한다. 앞뒤 설명, 여러 객체, 배열, 중복 키, 비문자 응답은 보류한다.
- 정책 v3는 v1/v2 응답 캐시를 재사용하지 않는다. v2의 한국어 인증번호·비밀번호 숫자 마스킹을 유지한다.
- 원본 작업본에도 같은 모델·파서·마스킹·요청 설정을 적용한다. 다른 재검토 UI, 팀 고정, 보존기간, 전송 로직은 이 변경에 포함하지 않는다.

## 기존 평가 근거 재확인

동일한 합성 73건을 모델별 두 번 실행한 원본 결과 146행씩을 확인했다. 기존 E4B, QAT, Q4 모두 pass 54, split 36, blocked 50, lossy 6이며 노출은 0이다. lossy 6은 프로젝트 맥락 없는 의료·가족·대출 업무 문장이 기존 규칙에 의해 보류된 사례다. 일반 업무 손실 0이라는 요약에서 이 여섯 보류를 제외했으므로 전체 업무가 모두 통과했다고 해석하면 안 된다. 프로젝트 맥락을 제공한 동일 업무 사례는 통과했다.

QAT 문장당 중앙값 0.945초, 기존 E4B 0.243초로 QAT가 느렸다. 보정된 OS 계측의 QAT 프로세스 footprint 최고 1.437GB, RSS 최고 6.572GB다. footprint와 RSS는 서로 다른 지표이며 QAT가 총 RAM 1.44GB만 쓴다는 뜻이 아니다. 최초 QAT 계측은 자식 프로세스를 놓쳐 메모리 비교에서 제외됐고 보정 결과를 사용했다. 이 작업에서 메모리 벤치마크를 다시 실행하지 않았다.

기존 근거는 로컬 `work/privacy-memory-final-{mlx,qat,q4}-20261108/quality.json`, `work/privacy-memory-os-{mlx,qat}-20261109/summary.json`과 metadata다. 원본 사용자 대화가 아닌 합성 사례이며 다른 기기·표현의 보편적 정확도를 보장하지 않는다.

## 재현

이번 반영본에서 개인정보·Pipeline 회귀 32개, 원본 작업본에서 29개가 통과했다. v1/v2 캐시 무효화 확대 검사는 양쪽에서 별도 재실행해 통과했다. 양쪽 모두 실제 QAT + 임시 DB로 업무·혼합·개인·합성 키·미설치 모델을 확인했다. 개인/미설치 입력의 외부 요청은 0, 혼합 입력은 개인 사유 제거 후 팀 A 승인 큐 한 건, 합성 키는 전송 직전 입력에서 제거됐다. 외부 AI는 실제로 호출하지 않았다. 원본의 관련 없는 기존 파일 해시는 모두 유지됐으며 모델 클라이언트·파서·마스킹 코드와 정책 설정을 맞췄다.

`python3 -B -m unittest check_local_privacy check_privacy_holds check_privacy_model_client check_pipeline`로 모의 응답 회귀를 실행한다. 설치된 실제 QAT는 `python3 -B check_privacy_memory_pipeline.py`로 검사한다. 후자는 임시 SQLite와 합성 입력만 사용하고 외부 AI 요청은 가로채며, 마지막에 테스트 모델을 해제한다.
