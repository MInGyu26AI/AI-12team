# Sync up 분류 기준표

## 1. 분류 기준
관련성 → 소주제 → 표시 순서로 판단 (민감정보는 어느 단계든 가림)

| 단계 | 분류 | 정의 · 들어가는 내용 | 신호 표현 (예) | 예시 문장 | 헷갈릴 때 |
|---|---|---|---|---|---|
| 1단계 관련성 | 관련 | 팀 이름 + 프로젝트 주제(팀 만들 때 입력)와 관련 있는 내용 | 프로젝트 주제와 연결되는 단어, 팀원 이름, 과제·발표·제출 | 주제는 청년 주거 문제로 하자. | 팀 이름만으로 판단하지 않고 프로젝트 주제를 함께 봄 |
| 1단계 관련성 | 개인 | 팀 프로젝트와 관련 없는 내용 (공유 안 함, 여기서 분류 끝) | 점심, 약속, 기분, 다른 수업, 병원 | 오늘 점심 김밥 먹었어. | "수요일 병원 가서 회의 못 가" → 개인. 회의 변경은 팀 합의 후 결정으로 기록 |
| 2단계 소주제 | 주제·목표 | 무엇을, 왜 하는지: 주제, 목표, 범위, 방향 | 주제, 목표, 방향, 범위, ~를 다루자 | 주제는 청년 주거 문제로 하자. | 범위를 정하면 주제·목표, 실제 만드는 방법은 작업·결과물 |
| 2단계 소주제 | 자료 조사 | 논문, 기사, 통계, 사례, 비교 결과 (조사 활동 자체) | 찾아보니, ~에 따르면, 통계, 사례, 비교해 보니 | 청년 월세 비중이 78%래. | 조사 내용 자체가 중심일 때만. 조사를 바탕으로 정했으면 해당 소주제의 결정 |
| 2단계 소주제 | 작업·결과물 | 실제로 만드는 것: 보고서 본문, 코드, 디자인, 실험 방법, 기획안 | 본문, 분석, 코드, 디자인, 실험, 초안, 구성 | 3장 분석은 회귀분석으로 하자. | 발표용 자료는 발표·제출 |
| 2단계 소주제 | 역할·일정 | 누가 무엇을 맡는지, 마감, 회의 시간 | ~가 맡아, ~까지, 회의, 모이자, 담당 | 자료 정리는 내가 금요일까지 할게. | 팀 내부 마감은 역할·일정, 교수님·주최 측 제출 기한은 발표·제출 |
| 2단계 소주제 | 과제 조건·피드백 | 교수님·주최 측 공지, 평가 기준, 분량·형식, 받은 피드백 | 교수님이, 공지, 평가 기준, 분량, 형식, 피드백 | 교수님이 10쪽 이내로 하랬어. | 팀이 정한 게 아니라 외부에서 주어진 조건 |
| 2단계 소주제 | 발표·제출 | 발표자, 발표 자료, 제출 방법과 기한 | 발표, PPT, 슬라이드, 제출, 업로드 | 발표는 유나가 하자. | 발표 담당을 정하는 것도 여기 |
| 2단계 소주제 | 기타 | 위 6개에 맞지 않는 팀 관련 내용 | — | 팀 규칙은 단톡방 공지로 하자. | 팀 이름, 팀 규칙 등 |
| 3단계 표시 | 결정 | 팀이 확정·합의·변경한 내용 → 충돌 확인 대상 | ~로 하자, ~로 정했어, 확정, ~로 바꾸자, ~하지 말자 | 분석은 군집분석으로 바꾸자. | "~하면 어때?" 같은 제안·질문은 결정 아님 → 공유 후보에서 제외 |
| 3단계 표시 | 할 일 | 누군가 해야 할 팀 작업 → 담당자·기한 추출 | ~할게, ~해야 해, ~까지, ~가 맡아, ~해 줘 | 자료 정리는 내가 금요일까지 할게. | "내가"는 말한 사람, 날짜 표현은 실제 날짜로. 없으면 미정 |
| 3단계 표시 | 조사 | 알게 된 사실, 조사 결과, 외부 조건 → 참고 자료 | ~래, ~에 따르면, 찾아보니, 교수님이 ~랬어 | 심사 기준에 AI 활용도가 있대. | 개인 취향("난 ChatGPT가 더 편해")은 개인. 소주제 '자료 조사'와 이름이 비슷하지만, 표시 '조사'는 사실·정보 전체(외부 조건 포함)를 뜻함 |
| 별도 검사 | 민감정보 | 전화번호, 주소, 계좌, 건강, 금융, 연애, 가족 정보 | 전화번호 형식, 계좌번호, 병원, 진단, 돈 문제 | 010-1234-5678로 연락 줘. | 관련 문장 안에 있어도 해당 부분만 가림 |

## 2. 회의록 대응표
회의록의 4분류(결정·조사·할 일·개인)와 이 기준표의 대응

| 회의록 4분류 | 이 기준표에서 | 어떻게 판단하나 | 예시 |
|---|---|---|---|
| 결정 | 관련 → 소주제(6개 중 하나) → 표시 '결정' | 확정·합의·변경 표현이 있는 팀 관련 내용 | 서비스명은 싱크업으로 정했어. → 관련 / 주제·목표 / 결정 |
| 조사 | 관련 → 소주제(주로 자료 조사, 과제 조건·피드백) → 표시 '조사' | 사실·자료·외부 조건 | ChatGPT 공유 프로젝트는 유료 플랜이 필요해. → 관련 / 자료 조사 / 조사 |
| 할 일 | 관련 → 소주제(주로 역할·일정) → 표시 '할 일' | 행동·담당 표현이 있는 팀 작업 | 기준표는 내가 내일까지 만들게. → 관련 / 역할·일정 / 할 일 |
| 개인 | 1단계에서 '개인' | 팀 프로젝트와 관련 없는 내용 | 오늘 점심 김밥 먹었어. → 개인 |
| 확장 | 2단계 소주제 | 팀 관련 내용을 활동별로 나눠 보드 정리에 사용 | 소주제·세부 주제가 달라도 '결정'끼리 충돌 비교 (같은 세부 주제 먼저) |

세부 주제(topic_key)는 보드에서 결정을 묶는 기준이고, 충돌 비교 순서를 정합니다. 팀 서버는 같은 팀에 먼저 올라온 유효한 결정 전체와 비교하고, 같은 세부 주제를 먼저 봅니다.

## 4. 출력 형식(JSON) — 백엔드(AI 담당) 전달용

| 필드 | 설명 | 값 예시 | 필수 여부 |
|---|---|---|---|
| sentence | 원문 문장(또는 나눈 일부) | 브라우저 확장도 MVP에 넣자. | 관련만 |
| relevance | 관련성: related / personal | related | 필수 |
| subtopic | 소주제: 주제·목표 / 자료 조사 / 작업·결과물 / 역할·일정 / 과제 조건·피드백 / 발표·제출 / 기타 | 작업·결과물 | 관련만 |
| tag | 표시: decision(결정) / todo(할 일) / research(조사) / none(제안) | decision | 관련만 |
| topic_key | 세부 주제 (보드 묶음·충돌 비교 순서, 기존 이름 먼저) | MVP 범위 | 관련만 |
| is_new_topic | 기존 세부 주제 목록에 없는 새 주제인지 | false | 관련만 |
| content | 정리된 내용 한 줄 | 브라우저 확장 = MVP 포함 | 관련만 |
| reason | 결정 이유 (있으면) | 대화 자동 수집이 있어야 시연 효과가 큼 | 선택 |
| owner | 결정자 또는 할 일 담당자 | 이서준 | 결정·할 일 |
| due | 할 일 기한 (YYYY-MM-DD, 없으면 null) | null | 할 일 |
| is_change | 기존 결정을 바꾸는 표현인지 | true | 결정 |
| source | 출처 (AI 종류·시간, 링크, 사람) | ChatGPT, 2026-11-06 21:10 | 필수 |
| masked | 민감정보를 가렸는지 | false | 필수 |
| confidence | 분류 확신도 (0~1). 0.6 미만이면 확인 필요 | 0.85 | 필수 |

- 개인(personal)은 sentence를 저장하지 않고 relevance와 필수 필드(source·masked·confidence)만 남깁니다.
- 프롬프트에 팀 이름, 프로젝트 주제, 켜 둔 소주제 목록, 기존 세부 주제 목록을 함께 넣어야 합니다.

예시 JSON:
{"sentence":"브라우저 확장도 MVP에 넣자.","relevance":"related","subtopic":"작업·결과물","tag":"decision","topic_key":"MVP 범위","is_new_topic":false,"content":"브라우저 확장 = MVP 포함","reason":null,"owner":"이서준","due":null,"is_change":true,"source":"ChatGPT, 2026-11-06 21:10","masked":false,"confidence":0.85}
