# 검증 범위와 근거

[서버 구현 안내로 돌아가기](README.md)

아래는 각 변경 당시 기록된 결과입니다. 문서를 정리하면서 모델·DB·브라우저 검사를 다시 실행한 것은 아닙니다. 검사 묶음은 서로 중복될 수 있으므로 건수를 합산하지 않습니다.

## 개인정보 필터

- 현재 QAT·정책 v3 반영 시 공유본 32개, 원본 29개 개인정보·승인 파이프라인 회귀가 통과했습니다. v1/v2 캐시 무효화도 따로 확인했습니다.
- 양쪽에서 실제 QAT와 임시 SQLite를 사용했습니다. 개인 입력과 미설치 모델은 외부 요청 0건, 혼합 입력은 개인 사유 제거 후 승인 큐 한 건, 합성 키는 전송 직전 입력에서 제거됐습니다. 외부 AI 요청은 가로챘습니다.
- 모델 비교는 고정 합성 73건을 모델별 두 번 실행했습니다. QAT에서 통과 54, 혼합 구간 분리 36, 차단 50, 맥락 없는 민감 업무 보류 6회였습니다. 보호 문구 노출은 관측되지 않았습니다.
- QAT는 기존 E4B보다 느렸습니다(문장당 중앙값 0.945초 / 0.243초). 보정 계측의 QAT RSS 최고치는 약 6.57GB이며, 모든 기기의 상한을 뜻하지 않습니다.

[현재 정책·테스트 명령](appendix/privacy-model-v3.md) · [실제 모델 → 필터 → 승인 검사](../check_privacy_memory_pipeline.py)

QAT 73건 원본과 OS 계측 파일은 개발 Mac의 별도 작업 폴더에 보관되어 있으며 이 저장소에는 포함되지 않습니다. 부록의 [기존 모델 평가 JSON](appendix/local-privacy-eval-20261108/)은 이전 Gemma3·Llama·Qwen 평가이므로 QAT 근거로 대체해 읽으면 안 됩니다.

## 결정 판정

실제 외부 AI로 기존 96회 평가를 재실행한 결과, 완료가 73회에서 78회로 늘었습니다. 기존 완료 사례의 퇴행과 완료된 240개 비교 쌍의 오판은 없었습니다. 남은 18회는 보류이며 성공에 포함하지 않았습니다. 원래 실패 사례와 새 사례 12회도 완료했습니다.

이는 고정 합성 사례의 결과이며 일반적인 정확도 추정은 아닙니다. 상세 요청·응답 파일은 개발 작업 폴더에 있고, 저장소에는 [분석과 평가 요약](appendix/decision-independent-review-20261108.md)이 있습니다.

## 진행 저장·팀 격리

실제 임시 PostgreSQL과 팀 HTTP API에서 65개 비교 완료, 중간 실패 후 재개, 프로세스 종료·재시작 복구, 타 팀 진행 정보 접근 차단을 확인했습니다. 이 묶음의 AI 응답은 제어된 합성 응답입니다.

브라우저에서는 7/40에서 중단된 검사를 재시도하고 새로고침 뒤 진행이 이어져 40/40이 되는 것을 확인했습니다. [결과 JSON](appendix/resumable-conflict-qa/verified-result.json) · [완료 화면](appendix/resumable-conflict-qa/completed.jpg) · [실행 조건과 한계](appendix/resumable-conflict-verification-20261108.md)

승인·마스킹·DB 복구·팀 접근 권한을 포함한 기존 통합 검증은 [당시 기록](appendix/integration-verification-20261108.md)에 있습니다. 그 기록의 모델과 배포 상태는 작성 당시 기준입니다.

## 아직 입증하지 않은 것

- 실제 사용자 대화 전체에 대한 개인정보 제거율과 AI 판정 정확도
- 여러 기기·장시간 운영·대규모 부하에서의 성능
- 이번 QAT 변경이 운영 클라우드에 배포됐다는 사실: 해당 변경은 `server`와 Mac 원본에 반영했고 클라우드는 재배포하지 않았습니다.

단위 검사, 실제 로컬 모델 검사, 브라우저 검사와 운영 배포는 서로 다른 확인 단계입니다.
