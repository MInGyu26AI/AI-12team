# 개인정보 처리

대화 원문은 이 Mac의 로컬 수집기에만 둔다. 외부 AI 분류 전에 기기 안에서 검사해 허용된 정리본만 보내고, 팀 서버에는 본인이 승인한 카드만 간다.

외부 AI 분석은 팀 공유 승인보다 먼저다. 팀에 공유하지 않은 대화도 외부 AI에는 이미 갔을 수 있다. 외부 AI의 개인·민감정보 기준은 [classification.md](classification.md)에 있다.

## 1. 어디로 무엇이 가는가

| 대상 | 받는 것 | 받지 않는 것 |
|---|---|---|
| 이 Mac (로컬 수집기) | 수집한 발화 전부(저장 전 형식 가림, 2절), 판정 기록, 후보 카드, 승인 전송 대기열 | — |
| 외부 AI (분류) | 허용된 발화의 정리본, 같은 대화 앞 묶음 중 허용된 문맥, 분류 정보(팀·사용자 이름, 프로젝트 주제, 켜 둔 소주제, 기존 세부 주제 이름) | 제외·보류된 발화, 개인 구간, 가린 키·연락처 |
| 팀 서버 | 승인한 카드와 내가 확인한 근거 발췌, 충돌 처리(이유 포함)·할 일 체크 | 원본 대화, 승인하지 않은 후보, 제외·보류된 발화 |
| 외부 AI (팀 서버의 충돌 검사) | 팀에 올라간 v2 결정 카드 (할 일·조사 카드는 안 감). 기기 안 검사 없이 `ai/` 가림 규칙만 적용 | 원본 대화 |

- 승인 전에 고친 후보 내용은 형식 가림만 하고 로컬 모델로 다시 검사하지 않는다.
- `ai/`의 명령줄과 평가 도구(`ai/eval`)는 외부 AI를 직접 부른다. 실제 대화로 돌리지 않는다.

## 2. 기기 안 검사

형식 규칙으로 키·연락처를 가린 뒤, 로컬 모델(`collector/privacy_model.py`)이 발화 하나씩 `work`·`personal`·`mixed`·`unsure`로 답한다. `mixed`면 개인 구간을 원문 그대로 돌려준다. 판정은 `collector/local_privacy.py`가 내린다.

- 사용자 발화는 앞 2000자, AI 답변은 앞 1200자만 검사하고 그만큼만 보낸다. 앞 묶음 문맥도 발화마다 검사한다. 분류 정보는 글자 값(이름·주제)에만 형식 규칙을 적용하고, 목록 값(소주제·세부 주제 이름)은 `ai/` 가림과 4절 검사만 거친다.
- 모든 입력과 재시도가 같은 필터를 지난다. 재시도 때는 원문부터 다시 가린다.
- 개인 단어 목록(건강·가족·연애·금전·종교·법률·위기·집 주소)은 모델 옆 안전망이다. 목록에 없다고 허용하지는 않는다. 프로젝트 주제에 든 단어는 세지 않는다 (주제가 `병원 예약 서비스`면 `병원`).
- 모델이 없거나 실패하면 외부 AI로 대신 판단하지 않고 보류한다.

| 판정 | 조건 |
|---|---|
| 허용 | 업무, 개인 단어 없음 |
| 허용 | 개인 구간을 `[개인사정]`으로 가린 뒤 개인 단어 없음, 업무 내용이 4자 이상·원문의 4분의 1 이상 남음 |
| 제외 | 개인 내용, 사용자 제외 |
| 보류 (60초 뒤 자동 재검사) | 모델 없음·시간 초과·HTTP 오류 |
| 보류 (사용자 처리 대기) | 쓸 수 없는 답, 판단 못 함, 업무인데 개인 단어 있음, 가린 뒤 개인 단어 남음, 직전 검사(4절)에 걸림 |
| 보류 (다음 실행에서 재검사) | 사용자의 다시 검사·제외 요청 |

| 발화 | 판정 | 외부 AI가 받는 것 |
|---|---|---|
| `병원 때문에 발표자료는 금요일에 공유할게` | 허용 (개인 구간을 가림) | `[개인사정] 발표자료는 금요일에 공유할게` |
| `수술 일정 때문에 이번 주 리뷰는 빠질게` | 보류 (모델은 업무로 봤지만 `수술`이 개인 단어) | 없음 |

묶음 안 발화 하나라도 보류면 묶음 전체가 보류다. 모두 제외면 외부 전송 없이 끝낸다. 그 밖에는 허용된 발화만 보낸다.

**형식 규칙** (`collector/privacy_rules.py`. 팀 정책이라 바꿀 때는 팀과 합의한다)

- Codex·Claude Code 발췌는 스캐너가 먼저 비밀값·이메일을 `[가림]`으로 바꾸고, 턴마다 600자 발췌 24개까지만 남긴다.
- 통합 모드는 저장 전에 `ai/syncup_ai/mask.py`가 흔한 키·토큰·비밀번호(`[API키]`·`[액세스토큰]`·`[비밀번호]`)와 연락처·이메일·주민번호·계좌(`010-1234-5678` → `[연락처]`)를 가린다.
- 그래도 남은 키·토큰·비밀번호류 비밀값은 검사 때 `[비밀키]`로 바꾼다. 잡는 형식은 `privacy_rules.py`에 있다.

## 3. 사용자 제외와 보류

보류된 묶음은 승인함(`/review`)의 '확인 필요' 탭에 발화별 판정·사유와 함께 나온다. 미리보기는 형식 규칙만 적용해 개인 내용이 보일 수 있다.

- '다시 검사': 그 묶음을 판정한 모델의 저장된 답을 지우고 다시 묻는다. 모델 설치·변경 뒤에 쓴다. 주제는 묶음을 만들 때 저장한 값을 쓰므로, 주제를 바꿔도 이미 만든 묶음의 판정은 달라지지 않는다.
- '분석에서 제외': 발화 하나, 또는 묶음에서 허용되지 않은 발화 전부를 제외한다. 남은 발화만 다시 검사한다.
- 두 요청은 다음 실행에서 처리되고, 그때까지 묶음은 보류로 남는다. 외부로 보내는 것은 없다 ([로컬 RPC](architecture.md#4-로컬-rpc)).
- 재검사(60초 자동 재검사 포함)는 수집 중일 때만 돈다. 일시중지·종료 중에는 보류가 그대로 남는다.
- '제외됨' 탭은 제외된 발화를 사유·시각과 함께 최근 200개까지 보여 준다.
- 제외는 되돌릴 수 없고 강제 전송도 없다. 로컬 원문은 6절 보존 규칙을 따른다.

## 4. 보내기 직전 검사

`collector/outbound_guard.py`가 보내기 직전에 본문 전체를 다시 본다. 단독 모드도 이 검사를 한다.

- 원문의 비밀값, 모델이 표시한 개인 구간, 허용되지 않은 발화의 문장 조각(8자 이상)이 남으면 보내지 않고 묶음을 보류한다. 통합 모드에서는 그 조각이 든 허용 발화도 보류로 바꿔 제외할 수 있게 한다.
- 앞 묶음 문맥에서 걸리면 그 문맥만 빼고 보낸다.

## 5. 저장 위치

모두 상태 폴더(`--state`)의 `private.sqlite`에 있다. 같은 폴더의 마이그레이션 백업(6절)에도 대화 내용이 들어 있다. 수집기가 만드는 파일은 현재 사용자만 읽고 쓰며, SQLite는 암호화하지 않는다. 로그·오류·상태 응답에는 원문을 넣지 않는다.

## 6. 보존 (7일)

`collector/retention.py`가 앱 시작 직후와 그 뒤 1시간마다 정리한다. 일시중지·종료 뒤에도 돈다.

| 대상 | 7일을 세는 기준 | 하는 일 |
|---|---|---|
| 원문·문맥, 정리본, 버린 후보의 내용 | 묶음 정리가 끝난 것을 처음 확인한 때 | 글자만 비운다 |
| 모델 답 캐시 | 기록한 때 | 행을 지운다 |
| 처리한 보관 입력 | 처리한 때 | 원문을 비운다 |
| 마이그레이션 백업 ([running.md](running.md#업그레이드와-백업)) | 파일 수정 시각 | 파일을 지운다 |

- 정리가 끝난 묶음은 분류가 끝났고, 카드가 모두 공유되거나 버려졌고, 전송 대기·차단이 없는 묶음이다.
- 승인하지 않은 후보, 보류, 분류 실패, 묶이지 않은 입력, 전송 대기·차단, 처리하지 않은 보관 입력은 기간과 상관없이 남는다.
- 승인한 카드와 전송 내용은 팀 기록이라 남는다. 팀 서버의 카드는 대상이 아니다 ([team-server.md](team-server.md)).

## 7. 로컬 모델 설정

이 Mac의 Ollama를 쓴다. 준비는 [running.md](running.md#개인정보-모델-준비)에 있다.

| 변수 | 기본값 | 설명 |
|---|---|---|
| `SYNCUP_LOCAL_PRIVACY_MODEL` | `gemma4:e4b-it-qat` | Ollama 모델 이름 |
| `SYNCUP_LOCAL_PRIVACY_URL` | `http://127.0.0.1:11434` | `http://127.0.0.1`·`http://[::1]`만 받는다. `localhost`라는 이름도 거절 |
| `SYNCUP_LOCAL_PRIVACY_TIMEOUT` | `90` | 초. 1~600 |

- 통합 모드는 `ai/.env`도 읽고, 셸 값이 우선한다.
- 모델 이름이 비었거나 설정이 잘못되면 전부 보류한다. 이름에 `cloud`가 든 모델과 Ollama가 원격에서 돌리는 모델은 거절한다.
- 저장된 답은 정책·모델별로 따로 둔다. 정책이 바뀌면 보류 묶음도 다시 판단한다. 모델이 바뀌면 그 뒤 검사부터 새 모델에 묻지만, 사용자 처리를 기다리는 보류 묶음은 '다시 검사'를 눌러야 다시 본다.

## 8. 알려진 한계

- 모델 판단은 확률적이다. 합성 문장으로만 검사했고, 실제 대화에서 새지 않는다는 보장은 없다.
- 프롬프트가 발화 안의 지시를 따르지 말라고 해도 모델이 주입 문장을 따를 수 있다.
- 주제에 없는 병원·가족·대출 같은 단어가 든 업무 문장은 보류된다. 이미 보류된 묶음은 제외해야 한다. 주제를 바꾸면 그 뒤에 만든 묶음부터 적용된다.
- 형식 규칙은 쪼개거나 인코딩한 토큰, 모든 제공자의 키 형식을 잡지 못한다.
- 같은 Mac의 다른 프로그램이 11434 포트에서 Ollama인 척하는 것은 막지 않는다.
- 단독 모드에는 보류 처리 화면이 없어, 60초 자동 재검사만 돌고 나머지 보류는 남는다.

검사: `local`·`model` 묶음 ([README 검사](../README.md#검사)). `model`은 개인 문장이 하나라도 새면 실패한다.
