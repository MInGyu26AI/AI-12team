# 테스터용 서버 AI

통합 수집기는 기본으로 `SYNCUP_AI_MODE=server`를 사용한다. 로컬 개인정보 검사와 OutboundGuard를 통과한 요청만 인증된 `/teams/{id}/ai/chat` 또는 `/ai/decide`로 보낸다. 공급자 키는 서버의 `OPENAI_API_KEY`에만 등록한다. 앱·확장·웹에 넣지 않는다. 개발자가 직접 호출할 때만 `SYNCUP_AI_MODE=direct`를 선택한다. 기존 단독 수집기·AI 평가 도구는 직접 호출 설정을 유지한다.

## 운영 순서

1. BYPASSRLS 권한이 있는 기존 함수 소유자로 `server/team_admin.py migrate-ai`를 실행한다. 새로운 `ai_calls` 테이블·인덱스와 제한 함수를 추가하며 기존 카드·팀 데이터는 변경하지 않는다. 재실행 가능하다.
2. 서버 코드를 배포한다. `SYNCUP_AI_PROXY_ENABLED=true`일 때 시작 과정에서 제한 테이블·함수 권한을 확인한다. 공급자 키 누락은 요청 시 503으로 응답한다.
3. 운영자가 Railway의 syncup-api / production 비밀 변수에 새 `OPENAI_API_KEY`를 직접 입력한다. 키를 채팅·명령 인수·소스·보고서에 적지 않는다. 해당 키는 기존 서버 충돌 검사에도 사용된다.
4. 새 서버 AI 지원 앱으로 합성 대화만 분류하고, 승인 전 팀 보드에 없는지 및 승인 뒤 공유되는지 확인한다.

## 제한

| 설정 | 기본값 | 허용 범위 |
|---|---:|---:|
| SYNCUP_AI_USER_MINUTE | 3 | 1–60 |
| SYNCUP_AI_USER_DAY | 30 | 1–1000 |
| SYNCUP_AI_TOTAL_MINUTE | 20 | 1–300 |
| SYNCUP_AI_TOTAL_DAY | 200 | 1–10000 |

분 한도는 최근 60초, 일 한도는 UTC 자정 기준이다. 사용자 한도는 팀을 바꿔도 합산된다. 원자적 DB 예약이므로 여러 서버 및 재시작에도 유지된다. 공급자 실패도 사용량에 포함하며 자동 환불·재시도하지 않는다. 서버 프로세스당 동시 4개, 본문 192 KiB, Responses 출력 최대 4096토큰, 공급자 응답 최대 2 MiB, 클라이언트 반환 최대 512 KiB. 모델·API 주소는 서버 코드에 고정되어 있다. 호출 수 제한은 결제 금액 상한이 아니며 기존 승인 후 충돌 검사에는 적용되지 않는다.

중계 요청·응답은 저장하지 않는다. 사용자 ID와 호출 시각만 저장하고 새 예약 시 UTC 이틀 전보다 오래된 기록을 정리한다(비활성 기간에는 다음 요청까지 남을 수 있음). 제한 테이블은 강제 RLS, 제한 함수는 고정 search_path와 재인증을 사용한다. syncup_api에는 테이블 직접 접근 권한이 없다.

검사: `python checks/check_ai_proxy.py` (Docker PostgreSQL 필요). 공급자 응답은 합성값이므로 실제 공급자 연결 검증과 구분한다.
