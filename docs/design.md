# 데이터 흐름과 처리 경계

[서버 구현 안내로 돌아가기](README.md)

## 개인 대화에서 팀 기록까지

```text
선택한 프로젝트의 대화 / 사용자가 가져온 입력
  → 로컬 SQLite에 수집
  → 규칙 마스킹 + 로컬 개인정보 모델
  → 허용된 문구만 외부 AI로 분류
  → 개인 검토함에서 후보와 근거 확인
  → 사용자 승인
  → 인증된 팀 API와 팀별 저장소
  → 기존 결정과 비교하고 진행 상태·결과 표시
```

외부 AI 분석은 팀 공유 승인보다 앞에서 일어납니다. 따라서 팀에 아직 공유하지 않았다는 사실이 외부 AI에도 전송하지 않았다는 뜻은 아닙니다. 외부 요청 전 로컬 검사를 적용하고, 사용자는 분석 동의와 팀 공유 승인을 각각 선택합니다.

## 외부 요청 전 개인정보 검사

비밀키·연락처·인증번호 등은 규칙으로 가립니다. 로컬 모델 `gemma4:e4b-it-qat`는 업무와 개인 내용이 섞인 문장에서 개인 구간을 판별합니다. 모델이 없거나 응답이 잘못되면 해당 입력은 보류합니다.

정책 v3는 완전한 JSON 객체 하나만 받습니다. 객체만 감싼 코드 블록은 허용하지만 설명문, 중복 키, 여러 객체는 거절합니다. 이전 정책의 판정 캐시는 재사용하지 않습니다. 프로젝트 맥락이 없는 민감 업무 문장은 보수적으로 보류될 수 있습니다.

구현: [local_privacy.py](../local_privacy.py) · [현재 모델·정책 검증](appendix/privacy-model-v3.md)

## 승인과 팀 격리

개인 검토 데이터는 로컬에 남고, 팀 저장소에는 승인한 문구와 근거만 전송합니다. 승인은 전송할 내용과 대상 서버·사용자·팀을 고정합니다. 이후 팀을 바꿔도 이미 승인한 대기열의 목적지는 바뀌지 않습니다.

서버는 요청자의 인증과 팀 소속을 확인합니다. PostgreSQL의 제한된 API 역할과 행 수준 접근 제어(RLS)도 팀 간 조회·쓰기를 제한합니다. UI에서 팀을 선택했다는 사실만으로 접근 권한을 인정하지 않습니다.

구현: [delivery.py](../delivery.py), [team_server.py](../team_server.py), [team_schema.sql](../team_schema.sql)

## 결정 비교와 복구

대상·범위·최종 값을 비교해 같음·변경·충돌·무관을 구분합니다. Decisions 판정이 0.6 미만이면 추론 모델이 독립 검토하고, 결정자 정보를 보완한 Decisions 판정으로 한 번 재확인합니다. 두 결과가 모두 기준 이상이며 일치할 때만 수용합니다. 그렇지 않으면 확인 필요로 남깁니다.

후보 유사도는 비교 순서를 정하며 후보를 잘라내는 기준으로 쓰지 않습니다. 팀 API는 비교를 나눠 수행하고 완료한 쌍과 진행 상태를 같은 트랜잭션에 저장합니다. 발견한 충돌을 먼저 보여줄 수 있지만, 남은 비교가 있으면 전체 검사는 완료로 표시하지 않습니다.

서버 전체 재시작 뒤에는 인증된 팀 요청이 한 번 있어야 작업이 다시 시작됩니다. 임대가 만료된 뒤 이어가며, 종료 전에 커밋되지 않은 요청은 다시 실행될 수 있습니다.

구현: [충돌 판정](../ai/syncup_ai/conflict.py), [팀 기록·진행 저장](../team_records.py)
